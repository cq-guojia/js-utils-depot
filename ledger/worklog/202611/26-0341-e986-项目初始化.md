## Background

用户要把散落在多个项目里的底层工具收敛成一个独立开源包，供前后端、多端共用。触发背景与已确认的决策如下（均由用户在 2026-11-26 会话中明确表态）：

- **现状与动机**：三个项目各有一套重复实现——`/code/dsh-plugins/dsh-plugin-core`（DSH 插件底座，`src/utils` 有日期/字符串/数值/路径/HTTP/中英字典，node 与单测可裸引）、`/code/open-lab/mp-taro-kit`（Taro 小程序基础库，`src/utils` 功能重叠但口径不同：相对时间单函数 `relativeTime`、默认只引中文、其他语言靠 `registerMessages` 注入、UTF-8 截断不用 `TextEncoder`）、`/code/koc/koc-weapp/koc-weapp-zuche-user`（老项目，依赖多年前的 npm 包 `koc-common-string` / `koc-common-datetimex` / `koc-common-sleep` 等，还挂着 moment 2.x）。老包在 npm 上多年未更新，需要被统一真源取代。
- **需求定性**：用户问过「需求合理不合理、能不能前后端统一」，答案是合理且能做到，但边界是「一套真源、四端按需引用」，不是零配置通吃。四端指 Node.js 后端、微信小程序、DSH 前端插件、DSH 后端插件；只有纯计算（字符串、小数、路径、日期格式化、相对时间计算）能统一，宿主能力（HTTP、DOM lang、文件、存储、官方 primitives）必须留在各端适配层。
- **包形态**：一个 npm 包、多子路径出口（`utils-kit/core/date`、`/core/string`、`/i18n`、`/locales/zh-cn`、`/vendor/*` 等），按需引用、按域打包；不做多个小包。每个子路径给 `types` / `import` / `require` 三件套，ESM + CJS 双产物，零 React / DOM / Taro / Node 内置依赖。根入口只是一张 re-export 清单。
- **语言方案**：核心零字典、语言包按需注入。外部端（DSH 插件）不限制体积，可一次注册全部语言；小程序只引中文包，其他语言不进包。`relativeParts()` 是语言无关的纯计算，文案由 i18n 层决定。
- **第三方策略**：不全部手搓。成熟且小的库直接引入并薄再导出（候选：`es-toolkit` 通用函数、`date-fns` v4 日期算术、`big.js` / `decimal.js-light` 小数精度），用户可在消费端选择用上游原版或本包定制版；第三方库作为运行时依赖而不是 devDependency。moment / lodash / dayjs / `Intl.RelativeTimeFormat` 已排除。
- **包名**：用户明确不要 KOC 前缀（KOC 是公司项目），不要二级包（无 scope）。查证 npm registry：`koc-*` 系列与 `shared-utils` / `common-utils` / `base-utils` / `core-utils` / `universal-utils` / `uni-utils` / `tiny-utils` / `utils-core` / `utils-base` / `utils-plus` 均已被占用；**`utils-kit` 无人占用，用户已确认用它**。
- **发布与落地位置**：所有开源包放在 `/code/open-lab/`，源码上 GitHub，包发 npm（不是 DSH 插件那种只走 git tag 的渠道）。顺序：先 GitHub 建仓库，再首次 `pnpm publish` 占 npm 名（可先发 `0.0.1` 占位版）。包管理器一律 pnpm；安装依赖需要用户单独授权。
- **本任务边界**：用户明确说这个任务「只做以下初始化工作：1. GitHub 的初始化 2. NPM 的初始化」。功能实现、utils 迁移、第三方接入、文档与自检都属于后续任务，不在本任务范围内。
